# hydro-s2 — мониторинг орошаемых полей по Sentinel-2

Сайт: **https://ahmetkalia23-hue.github.io/hydro-s2/**

24 пилотных поля проекта Hydrosat (Жамбыл — кукуруза, люцерна, свёкла, фасоль;
Туркестан — хлопок). 16 спектральных индексов, гистограммы распределений,
попиксельные вырезки полей, экспорт CSV. Тикеты HYD-3 … HYD-11.

## Как устроено

```
data/                 исходные данные (источник истины)
  fields/fields.shp   границы 24 полей
  stats.parquet       поле × дата: 16 средних + персентили, CV, облачность
  histograms.parquet  длинный формат: поле × дата × индекс × бин
build/
  mpc.py              доступ к Microsoft Planetary Computer (STAC, SAS-токен, чтение окон)
  core.py             формулы индексов, бины гистограмм, обработка сцены
  update.py           инкрементальное обновление (HYD-7)
  render_chips.py     PNG-вырезки полей для карты
  build_data.py       JSON для сайта из parquet
site/                 статический сайт (Leaflet + Chart.js), публикуется на Pages
```

## Обновление данных

Ежедневно в 03:00 по Алматы GitHub Actions запускает `build/update.py`: он берёт
последнюю дату из `data/stats.parquet` и досчитывает только снимки после неё
(с нахлёстом 3 дня — L2A иногда публикуется с задержкой). Если новых сцен нет,
прогон заканчивается за секунды. Если есть — обновляются parquet, вырезки полей
и JSON, изменения коммитятся, сайт пересобирается автоматически.

Вручную:

```bash
python build/update.py                    # добрать новое
python build/update.py --dry-run          # посмотреть, что появилось
python build/update.py --from 2026-03-01  # пересчитать период заново
```

Через интерфейс GitHub: вкладка Actions → update-data → Run workflow
(там же можно указать дату и режим dry-run).

## Методика

Sentinel-2 L2A через Microsoft Planetary Computer. Маска облаков SCL (класс 3
и ≥ 8), гармонизация baseline (−1000 с 2022-01-25), контроль облачности по
каждому полю отдельно (в ряды идут даты с ≥ 95 % чистых пикселей), дедупликация
поля, попавшего в два перекрывающихся тайла, по максимуму чистых пикселей.

Средние считаются на сетке 10 м. Распределения индексов, использующих
20-метровые каналы (NDRE, RECI, NDMI, NDTI, STI, NDSVI, BSI) — на нативных 20 м:
билинейный апсемплинг искусственно сужает гистограмму. Гистограммы строятся при
≥ 50 валидных пикселях, границы бинов фиксированы, поэтому распределения
сравнимы между датами, полями и сезонами. Перед расчётом граница поля сжимается
на 10 м внутрь, чтобы краевые пиксели (арыки, дороги, лесополосы) не искажали
статистику.

Флаг `implausible` поднимается, когда среднее по полю выходит за физический
потолок (NDVI > 0.92, GCI > 12, RECI > 6, NDMI > 0.6).

## Известные проблемы данных

1. **Поле 4** (фасоль, 12.4 га) — NDVI до 1.02, 7 дат с флагом `implausible`.
   Граница почти наверняка захватывает не посев (теплица, сад, лесополоса).
   Проверить полигон до включения в отчёт.
2. **Хлопковый кластер** (поля 20–24) — максимум NDVI 0.50–0.62 против 0.75–0.90
   у кукурузы и люцерны, плюс разрыв 28.04–02.06 из-за облачности. Сверить
   границы с данными выездов до выводов об угнетении.
3. **Поля 2 и 3** (1.0 и 0.79 га) — на сетке 20 м меньше 50 пикселей, гистограммы
   водного блока для них не строятся (`<индекс>_hist = false`).
